# ИСУП Монитор

Парсер обходит реестр ОКС, открывает карточки объектов и выгружает участников из раздела «Управление проектами».

Для запуска укажите `ISUP_URL`, `ISUP_LOGIN` и `ISUP_PASSWORD` в файле `.env`.

```sh
uv run playwright install chromium
uv run isup-monitor > projects.json
```

Для пробного запуска добавьте `--limit 3`. Чтобы видеть окно браузера, добавьте `--headed`. Участники каждого объекта записываются в поле `participants`. Если список пуст, поле содержит `[]`. Если список прочитать не удалось, поле содержит `null`, а причина сохраняется в `participants_error`. Ошибки обхода также выводятся в stderr.

Чтобы получить 34 поля листа «Объекты» в порядке раздела 5.1 ТЗ, используйте режим отчёта.

```sh
uv run isup-monitor --report --limit 3 > objects-report.json
```

### Запись снимков в PostgreSQL

В Docker Compose приложение и PostgreSQL запускаются в отдельных контейнерах. Укажите в `.env` настройки ИСУП и значения `DB_USER`, `DB_PASS`, `DB_NAME`. В контейнере приложение подключается к `postgres:5432` и применяет миграции перед выгрузкой.

```sh
docker compose run --build --rm app --save-db --limit 1
```

Для полного обхода уберите `--limit 1`. В контейнере Chromium запускается в фоновом режиме. После выгрузки контейнер приложения завершает работу, а PostgreSQL продолжает работать и хранит снимки в Docker-томе.

#### Запуск парсера на хосте

Заполните в `.env` параметры `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASS` и `DB_NAME`. Для локальной базы задайте `DB_HOST=localhost` и запустите PostgreSQL через Docker Compose. Если у вас уже есть работающий сервер PostgreSQL, примените миграции на нём.

```sh
docker compose up -d --wait postgres
uv run alembic upgrade head
uv run isup-monitor --save-db
```

Для пробного запуска добавьте `--limit 1`. Объект сохраняется сразу после обработки карточки. Пробный снимок получает статус `partial`. Если обход завершился с ошибкой, снимок получает статус `failed`, а журнал сохраняет причину. Для отчётов выбирается последний снимок со статусом `ready`. Чтобы одновременно записать снимок и вывести JSON, добавьте `--report`.

Отчёт выгружается в JSON. Поля без подтверждённых данных остаются `null`. Команды и число людей читаются в разделе «Информационный обмен → Модуль заказчика (ЭДО)». Операции считаются по столбцу «Дата документа» в «Документации». Финансовые данные берутся из паспорта объекта. Если отдельного поля «Освоено» нет, используется сумма «Оплачено». Порог для вывода «нет обмена более N дней» задаётся параметром `--exchange-threshold` и по умолчанию равен 7.

### Локальный API

Запустите `docker compose up -d --build --wait api` и откройте Swagger по адресу
`http://localhost:8000/docs`. При необходимости задайте `API_PORT` в `.env`.

- `GET /health` проверяет запуск приложения.
- `GET /api/v1/projects` возвращает объекты последнего готового снимка. Поддерживает фильтры `stage`, `state`, `customer`, `status` и параметры `offset`, `limit`.
- `GET /api/v1/projects/{oks_number}` возвращает поля отчёта по одному объекту.
- `GET /api/v1/snapshots/latest` возвращает метаданные последнего готового снимка.
- `GET /api/v1/ingestions` возвращает журнал запусков с пагинацией.

Маршруты объектов и снимка возвращают 404, пока нет снимка со статусом `ready`. API доступен на localhost для разработки. Вход через Яндекс ID и права доступа предстоит подключить перед развёртыванием для пользователей.
